# Resolved non-Agent developer entities in the Claude-attributed commit corpus

## Main findings

The analysis ranks resolved non-Agent developer entities by the number of unique global commit SHAs on which they appear as primary author, declared co-author, or both. The Top-10 is led by `screwyforcepush` with 1,236 union global SHAs, `ruvnet` with 582, and `Dicklesworthstone` with 350. The ten entities sum to 3,395 identity-level union global-SHA observations and 4,643 repository-SHA exposures. The same SHA can be associated with more than one identity, so these are identity-level totals rather than a count of mutually distinct commits across people.

The Top-10 has a clear skew towards people who build AI-assisted development infrastructure. It does not look like a cross-section of ordinary Claude terminal users. At least six accounts maintain Agent orchestration, Model Context Protocol integrations, multi-Agent communication, AI-assisted verification, or related developer tools. Others work on repository automation or scientific Agent systems. This fits an attribution-based corpus: developers with repeatable Agent workflows are more likely to leave consistent commit signals than occasional interactive users.

Claude-attributed development also appears in technically demanding fields. The reviewed projects cover formal logic and theorem proving, PCB design automation, parametric engineering, scientific workflows, WiFi sensing, vector and memory systems, machine-learning infrastructure, and MLOps education. In these projects, coding Agents sit alongside specialist knowledge, project architecture, and domain-specific validation.

The ranking brings together very different workflows. `screwyforcepush` has sustained activity in one repository. `ruvnet` has a co-author-heavy footprint spread across 365 repositories. `hyperpolymath` combines 140 repositories with a 150-SHA peak day, which is consistent with estate-wide synchronisation. `eakarsu` has exactly one SHA in each of 124 repositories on one date, and `ywatanabe1989` shows a smaller ecosystem-wide burst. Union global SHA is best read as an identity-level workflow footprint within this corpus.

The counting unit changes the ranking substantially. Only 3 of the union global-SHA Top-10 also appear in the repository-SHA exposure Top-10. Global SHA removes repeated appearances of the same hash across repositories; repository-SHA records how widely a commit appears. Forks, mirrors, templates, copied histories, and coordinated maintenance can therefore change who appears near the top.

## Dataset and ranking method

The frozen population contains 401,025 Claude-eligible repository-SHA records. Each record was matched by `repository_id + commit_sha` to the corresponding raw GitHub Search API result to recover the full commit message, Git author and committer fields, the top-level GitHub account object where present, and frozen repository metadata. The RQ1 population was neither rebuilt nor modified for this exploration.

Top-level GitHub author linkage was available for 332,273 records, or 82.86%, and missing for 68,752 records, or 17.14%. Offline resolution through GitHub noreply formats and unambiguous one-to-one mappings inside the frozen corpus linked another 905 primary-author records. After this step, 67,847 primary-author repository-SHA records remained unresolved, or 16.92% of the population.

Primary authors and co-authors are linked through GitHub identifiers, noreply addresses, and unambiguous mappings found inside the frozen corpus. Known Agent signatures are classified separately; unresolved addresses receive internal HMAC keys, and names alone are never merged. The resulting 150,233 keys include accounts, services, unresolved records, and 282 event-specific missing-primary keys.

Co-authors are read from the final trailer block of each commit message. The parser handles multiple or repeated co-authors, malformed entries, Unicode, and different line endings. The five parser states close exactly over the population:

| Trailer parser state | Repository-SHA records | Share |
|---|---:|---:|
| `valid_coauthor` | 356,916 | 89.00% |
| `valid_and_malformed_coauthor` | 130 | 0.03% |
| `malformed_coauthor_only` | 152 | 0.04% |
| `terminal_trailer_no_coauthor` | 25,951 | 6.47% |
| `no_terminal_trailer` | 17,876 | 4.46% |
| **Total** | **401,025** | **100.00%** |

In total, 357,046 commits contain at least one valid co-author trailer. There are 282 commits containing malformed co-author material and 283 malformed trailer lines. Because Claude-related trailer text was one accepted attribution channel, these frequencies describe this corpus rather than GitHub generally.

The reviewed ranking includes resolved non-Agent people, team-operated accounts, and Organizations. Agent identities, Bots, automation, uncertain accounts, and unresolved or placeholder keys are excluded with recorded reasons. All ten entries happen to be individual accounts; Organizations were eligible but none reached the Top-15.

The main score is `union_global_sha_count`: one observation per identity and commit SHA, whether the identity appears as author, co-author, or both. Repository-SHA counts show cross-repository exposure, and their ratio to union global SHA gives the duplication factor. Ties use author SHA count, repository count, active days, and a stable identity key. Temporal and message statistics are global-SHA deduplicated; repository concentration is not.

## Sensitivity, unresolved identities, and validation

The counting units answer different questions:

| Unit | Definition | Interpretation |
|---|---|---|
| Global SHA | One commit hash counted once per identity across repositories | Cross-repository-deduplicated commit observation |
| Repository-SHA | One repository and commit-hash pair | Commit exposure within repository contexts, including propagation |
| Author global SHA | Unique SHAs with the identity as primary Git author | Primary-author attribution |
| Co-author global SHA | Unique SHAs declaring the identity in a terminal co-author trailer | Declarative co-author attribution |
| Union global SHA | Unique SHAs containing either role, with same-SHA overlap removed | Main exploratory ranking unit |

Only 3 of the global-SHA Top-10 also occur in the repository-SHA Top-10. `ruvnet` shows the largest gap among the final ten: 582 union global SHAs become 1,788 repository-SHA exposures, for a duplication factor of 3.07. Repository-SHA captures ecosystem reach and propagation; global SHA gives the more stable rank for distinct observed commits.

Seven unresolved email keys met or exceeded the conservative review cutoff of 124 union global SHAs. No other unresolved key fell between the final tenth-place value of 114 and 123, so the same seven covered all unresolved candidates numerically capable of entering the Top-10. A targeted review made 35 GitHub GraphQL commit-author queries. One key resolved in 5 of 5 sampled repositories to [`happy-otter`](https://github.com/happy-otter), a publicly described remote-control service for coding Agents, and was classified as an Agent service identity. The remaining six keys span 48 to 347 repositories and 4 to 161 inconsistent display names. Among 30 targeted queries, 29 returned matching author nodes but none linked to GitHub accounts, supporting their classification as shared placeholder-email clusters. None was eligible for the non-Agent table, and the Top-10 remained unchanged.

The completed analysis binds 22 frozen inputs, 16 derived outputs, and 8 scripts or rule files. All 46 base size and SHA-256 bindings were independently verified with zero mismatches. The targeted unresolved-identity extension raises the total to 55 bound artifacts, also with zero mismatches. Fifteen tests passed. The invariants cover unique matching of all 401,025 population records to raw records, parser-state closure, same-SHA union deduplication, conflicting email mappings, event-specific missing-primary keys, and recorded reasons for all 35,194 audit exclusions.

## Overall interpretation and scope

The leading accounts work on multi-Agent coordination, MCP tooling, formal verification, engineering automation, scientific workflows, AI systems, and MLOps education. Their commit records range from sustained work in one repository to ecosystem-wide propagation and coordinated maintenance across many repositories. The differences help explain how Agent attribution appears in real software projects.

The scope remains the frozen Claude-attributed corpus and its resolved subset. Top-level identity linkage misses 17.14% of repository-SHA records and 16.92% remain unresolved after offline linkage. Global SHA measures deduplicated commit observations, repository-SHA measures exposure, and public profiles provide context about technical direction. Account activity can also involve organisations, teams, automation, or imported history. Within these boundaries, the reviewed Top-10 and its central conclusions are stable under the completed cutoff-focused unresolved-identity check.
